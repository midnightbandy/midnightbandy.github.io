Flock

The app that handles everything about getting people together, so the only thing you have to do is show up.

Next.js 16React 19SupabaseWeb Push

What it is

Started as a hangout-coordination app. What it actually became: trust infrastructure for presence. Four primitives carry the whole product — Tally (a computed 0–100 trust score), Carry (what a guest commits to bringing, assigned before they're confirmed), Clink (the invite token and the full audit trail Tally is built from), and Flock itself (the event — the atomic unit).

Tally weighs four dimensions: reliability (did you show up), carry quality (did you bring what you said), vibe contribution (would the host invite you again), and authenticity (phone-verified, vouched-for). It's designed to be expensive to game — the product's own standing rule is that no feature ships if it would compromise the integrity of that score, full stop.

The architecture decision that shapes everything else

Flock never holds an OAuth access token for any third-party account, for any provider — a permanent decision, not a temporary limitation. Every integration is one of three shapes: a deeplink that hands the user off to finish in another app themselves (a ride-booking app, a food delivery app, a UPI payment app), a no-auth public API call with zero user credential, or the honest answer that it isn't connectable at all.

A generic OAuth2 connector engine was actually built at one point — real token exchange, real CSRF handling — then deleted outright once it was confirmed to be holding zero live tokens for any real user. That's the standard the product holds itself to: not modeling a feature as "pending," building it if it's real.

Where it stands

The core loop — set up a space, get a suggested activity from what's actually in the room, host an event, check guests in by QR, rate each other after, watch the trust score recompute — is real and wired to a live database, not a prototype. Payment settlement uses UPI deeplinks directly; no payment processor was needed for the peer-to-peer case. Engineering-complete-ish, still pre-launch.

Honest state: no production URL exists yet. The backend, the trust engine, and the automation are real and tested; going live is a deploy decision that hasn't been made, not an engineering blocker.
